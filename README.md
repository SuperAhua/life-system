## 一、这是什么

大多数人回望 25–35 岁，后悔的不是没赚到钱，而是**健康透支、错过积累、放弃了关系**。

这个工具把这句话拆成四条线：

| 线 | 一句话 | 颜色 |
|---|---|---|
| 健康 | 身体是所有目标的底座 | 绿 |
| 财务 | 不透支，也别让钱闲着 | 琥珀 |
| 能力 | 一项别人难以替代的本事 | 蓝 |
| 关系 | 父母的陪伴有期限 | 玫红 |

围绕这四条线，它只做三件事：

1. **今天**：把清单里该做的事摆出来，点一下记录（做了 / 最小版 / 没做）
2. **训练**：跟练计时，一个动作一个动作走完，自动落库
3. **回顾**：每周回答三个问题，每季度给四条线打分，看哪条在透支

它不追求"全"，追求**能长期用下去**。所以没有等级、没有徽章、没有连续打卡惩罚，也没有排行榜。

## 二、五分钟上手

### 打开

双击 `生命系统.html`，用 Chrome / Edge / Safari 打开即可。也可以拖进浏览器窗口。

手机上不用传文件：直接开 [线上地址](https://superahua.github.io/life-system/)，再「添加到主屏幕」（见第十节）。

### 第一次打开会看到什么

- 已经预置了 8 条清单（四条线各 2 条），可以直接用，也可以全改掉
- 顶部四个页签：**今天 / 训练 / 回顾 / 清单**
- 右上角齿轮：数据与设置

### 每天（30 秒）

打开「今天」，从上往下做。做完点「做了」；状态不好点「最小版」——它也算数。

### 每周（5 分钟）

去「回顾 → 本周复盘」，先看上半部分的自动统计，再回答三个问题，保存。

### 每季度（10 分钟）

去「回顾 → 季度体检」，四条线各给「现在」和「期望」打个分，看差距最大的那条。

### 训练（想练的时候）

去「训练」，按下绿色大按钮「开始跟练」，跟着倒计时走。

## 三、四个页面

### 1. 今天

**这一个页面的主动作：记录今天。**

- **抬头一句判断**：今天还剩几件 / 都记完了 / 某条已经几天没做。只给一句，不刷屏。
- **本周重点**：只写一件，做完就算赢。随时可改。
- **今日清单**：按时间排序。每条显示时机、频率、本周进度；当前该做的那条会被标上「现在」。
- **三种状态**：做了（绿）/ 最小版（琥珀）/ 没做（红）。再点一次可以取消。
- **展开行**（点标题）：看到 SOP 步骤、最小版、上次记录，还能写一句备注。跟练条目的底部多两个入口：「换一套」「去训练页 ›」。
- **跟练条目**多一个「开始跟练」，直接进计时器。
- **右栏「这一周」**：7 根竖条（当天完成率）+ 四条线的本周完成度 + 连续天数。

底部还有「补记昨天」，忘了勾的可以补。

### 2. 训练

**这一个页面的主动作：开始一次跟练。**

- **抬头一句判断**：本周还差几次 / 今天练过了 / 本周已达标。
- **训练卡**：名称、频率、模板名、动作数、预计时长、本周进度点、绿色大按钮「开始跟练」。
- **按钮下方一行**：换一套动作 / 看动作 / 今天的状态（做了·最小版·没做）。
- **动作清单**（点「看动作」展开）：每行是「动作名 + 右对齐的量」，例如「深蹲 4 组 × 15 个 · 4 组」。组间休息不会写进正文，只在计时里生效。
- **最小版提示**：今天实在不行做这个。
- **右栏**：
  - 训练记录：本周次数、本周时长、本月次数、累计时长 + 7 天打卡条
  - 最近 8 条：日期、名称、分钟数、体感
  - 练过什么：从计时记录里摘出的动作组合（只在有记录时出现）

如果一条跟练都没有，页面会给一个「+ 加一条训练」，点开就是预填好的表单。

### 3. 回顾

顶部分段控件切换两个视角。

#### 本周复盘

- **这周的样子**（自动统计，不用你填）：四条线完成率、做了 / 最小版 / 没做各几条、记成没做的清单、你写过的备注。
- **周复盘三问**：这周做成了什么 / 哪里没做好、为什么 / 下周最重要的一件事。加一个 1–5 分自评。
- **最近 18 周热力图**：一格一天，颜色越深当天完成率越高，点格子能补记那一天。
- **复制给 AI**：把本周真实数据整理成一段话，粘到任何对话框里就能问"这周该改哪件"。

#### 季度体检

- **现状 / 期望双滑块**：每条线两条轨道，上面是现在，下面是期望。1–10 分。
- **雷达图**：形状就是你的四条线。
- **差距提示**：自动指出差值最大的那条，并建议「这个季度只补这一条」。
- **历次**：保存过的每次体检，显示四线均值与相对上次的 Δ。
- **算一算**：月存 × 年化 × 年数 → 复利终值，同时算出「晚 5 年开始会少掉多少」。

### 4. 清单

**这一个页面的主动作：维护清单。**

按四条线纵向分组。每行只有名称、标签（跟练 / 频率）、编辑按钮。所有增删改都在弹窗里完成，避免误触。

### 设置（右上齿轮）

- **使用说明**：这份 README 已经内嵌进应用，离线也能看（顶部目录可一键跳到对应章节）
- 记录天数 / 记录次数 / 累计时长
- 导出 JSON / 导入 JSON / 清空所有记录
- 复制上下文（给 AI 的复盘）

## 四、核心概念

### 三态记录

| 状态 | 权重 | 什么时候用 |
|---|---|---|
| 做了 | 1.0 | 按计划完成 |
| 最小版 | 0.6 | 状态差，只做了台阶版 |
| 没做 | 0 | 明确没做 |

**为什么要有「最小版」**：只记「做了 / 没做」时，状态一差就只能记「没做」，连着记几天人就不想记了。留一个 0.6 的台阶，记录才不会断。

完成率 = Σ权重 ÷ 本周目标次数。所以会出现 `2.6/3` 这种小数，这是正常的。

### 每条清单的四要素（SOP）

1. **叫什么** —— 具体到能直接开始。写「运动 30 分钟」而不是「多运动」。
2. **什么时候** —— 给一个时间点，工具会把它排进今天，并在到点后标「现在」。
3. **分几步** —— 一行一步，最多 12 步。步骤的作用是降低启动成本。
4. **最小版** —— 今天实在不行时做的那一步，通常就是"换好衣服"。

### 频率的四种类型

| 类型 | 含义 | 本周目标 |
|---|---|---|
| 每天 | 天天做 | 7 |
| 每周 N 次 | 一周内任意 N 天 | N |
| 每周固定几天 | 只在选定的星期出现 | 选定天数 |
| 每月某天 | 每月固定日期 | 1 |

「每天」和「每周 N 次」的条目会出现在每天的清单里（因为哪天做由你决定）；「每周固定几天」和「每月某天」只在对应日子出现。

### 连续天数

只要当天**任意一条**有记录就算。今天还没记时，从昨天往前数——所以早上打开不会看到「连续 0 天」。

断签不清零、不飘红，只是数字停住。热力图里斜纹表示"那天没记录"，不等于"没做"。

## 五、训练模块

### 三个入口

1. 顶部页签 **训练** —— 看计划、换模板、看历史
2. 今天页跟练行的 **开始跟练** —— 一键直接进计时器
3. 今天页展开面板底部的 **去训练页 ›** —— 带着这条跳到训练页并展开动作

### 什么算「跟练」

清单里的条目如果是「跟练（带计时）」类型，就会：

- 在「今天」的行里多出一个「开始跟练」按钮
- 出现在「训练」页
- 记录时能存下用时、体感、做了哪些动作

普通条目只有三态记录，没有计时。

### 六套预置模板

| 模板 | 侧重 |
|---|---|
| 全身唤醒 | 唤醒 + 全身循环，适合早上或久坐后 |
| 下肢 | 深蹲、箭步蹲、臀桥、静蹲 |
| 上肢 | 俯卧撑、推举、划船、卷腹 |
| 核心 | 平板、抬腿、死虫、登山跑 |
| 有氧 | 快走、慢跑、跳绳、波比 |
| 恢复 | 慢走、泡沫轴、猫牛式、拉伸 |

每套 6 行。点「换一套动作」可以整体替换步骤，**历史记录不受影响**。

### 计时是怎么工作的

每条步骤会被自动解析：

```
深蹲 4 组 × 15 个，组间休息 60 秒
   ↓
组数 4 · 组间休息 60 秒 · 单组不设倒计时（按次数做）
```

```
平板支撑 3 组 × 45 秒，组间休息 30 秒
   ↓
组数 3 · 单组 45 秒倒计时 · 组间休息 30 秒
```

规则：

- `N 组` → 组数（1–12）
- `组间休息 / 组间歇 / 组间 / 休息 / 间歇 + 数字 + 秒/分钟` → 休息时长
- 第一个「分钟 / 分」→ 单组倒计时；没有分钟时取「秒」
- 写了组数但没写休息 → 默认 45 秒
- 只写「3 公里」「20 个」这类 → 不倒计时，做完手动点

**不用写得规范**，认不出来就退化成「按次数做，做完点完成这组」。

### 一次完整跟练

1. 「开始跟练」→ 抽屉里先看一遍今天的动作清单
2. 点「开始」→ 进入第 1 组
3. 有秒数的自动倒计时，到点响一声（880Hz，160ms），自动进休息
4. 休息结束自动进下一组
5. 按次数做的，做完点「完成这组」
6. 四个按钮随时可用：完成这组 / 跳过这个动作 / 暂停 / 提前结束
7. 走完最后一组 → 「练完了」页：用时、完成动作数、跳过数
8. 选一个体感（轻松 / 刚好 / 偏难），点「存进今天」

存进去的内容：

```
st:   done          （状态）
mins: 28            （用时，多次累加）
feel: normal        （体感）
sum:  原地踏步 3 分钟；开合跳 3 组 × 30 秒；…   （做过的动作，≤140 字）
```

体感会进周复盘和给 AI 的上下文，下次「换一套」时可以据此调整强度。

### 训练页的统计口径

| 指标 | 口径 |
|---|---|
| 本周次数 | 本周内状态为「做了」的记录数 |
| 本周时长 | 同上，累加 mins |
| 本月次数 | 本月内「做了」的记录数 |
| 累计时长 | 所有训练记录的 mins 之和 |
| 7 天条 | 哪天有「做了」就亮 |

**最小版和没做不算次数**，只出现在「最近」列表里——避免"点一下最小版就当练过"的自我安慰。

### 响铃没声音？

浏览器要求先有一次用户交互才允许播放音频。点过页面任意位置后再开始即可。如果仍然没声，检查系统是否静音、浏览器是否限制了自动播放。

## 六、回顾：周复盘与季度体检

### 自动统计（不用填）

打开「本周复盘」，上半部分已经替你算好：

- 四条线的完成率（加权）
- 做了 / 最小版 / 没做各几条
- 记成「没做」的具体条目和星期
- 这一周你写过的备注

### 三个问题

1. **这周做成了什么** —— 写事，不写感受
2. **哪里没做好，为什么** —— 是时间不够，还是根本没开始
3. **下周最重要的一件事** —— 只写一件

加一个 1–5 分的整体自评。保存后进历史，右下角可以看更早的。

### 热力图

最近 18 周，一格一天。颜色分 5 级（无记录 / <34% / <67% / <99% / 100%）。点任意一格打开那天的补记面板。

### 季度体检

- 四条线各两个滑块：**现在** 和 **期望**
- 雷达图看形状，不看绝对高低
- 差距最大的一条会被点名，并建议这个季度只补它
- 每次保存进「历次」，带均值与 Δ
- 底部的复利计算器：默认月存 3000、年化 5%、10 年 → 约 46.6 万；晚 5 年开始只剩 20.4 万

### 复制给 AI 的上下文

点「复制给 AI」，生成的文本包含：

```
【我的四线周报】11月25日 周三
健康：本周 3/3（100%），做了 3、最小版 0、没做 0
财务：…
上次体检：健康 6/期望9，…
本周重点：…
训练：本周 3 次、101 分钟；累计 56 次、1724 分钟

【本周明细】
11/25 运动 30 分钟 = 做了 28分 刚好 内容:…
…

【上次复盘】做成：…；卡在：…；下周重点：…

请基于以上真实数据回答：1）这周哪条线透支最明显；2）下周只改一件事的话，改哪件；3）给一个能立刻做的最小动作。不要泛泛而谈。
```

粘到 DeepSeek / 豆包 / 任何对话框都能用。**不联网、不存 API Key**，这是刻意的选择。

## 七、清单管理

在「清单」页点「+ 加一条」或任意条目的「编辑」。

| 字段 | 说明 |
|---|---|
| 叫什么 | 具体到能直接开始 |
| 属于哪条线 | 健康 / 财务 / 能力 / 关系 |
| 类型 | 普通 / 跟练（带计时） |
| 频率 | 每天 / 每周 N 次 / 每周固定几天 / 每月某天 |
| 什么时候做 | 时间点，用于排序和「现在」标记 |
| 大概多久 | 分钟，仅作展示与训练页参考 |
| 分几步 | 一行一步，最多 12 步 |
| 最小版 | 今天实在不行时做的那一步 |

底部三个操作：**停用 / 删除 / 保存**。

- **停用**：从今天清单里消失，但历史记录保留，随时可以启用
- **删除**：连同历史记录一起删掉，不可恢复（会二次确认）

> 建议四条线加起来不超过 16 条。超过之后完成率一定会掉，掉完就不想看了。

## 八、数据与备份

### 存在哪

浏览器的 `localStorage`，键名 `life.v3`。**不上传、不联网、没有服务器。**

这也意味着：**换设备、换浏览器、清缓存，数据就没了。** 请定期导出。

### 导出

设置 → 导出 JSON，文件名形如 `生命系统备份-2026-11-25.json`。

### 导入

设置 → 导入 JSON，选择之前导出的文件。会校验版本：v3 直接读，旧版自动迁移。

### 数据结构

```jsonc
{
  "v": 3,
  "start": "2026-11-20",          // 开始使用的日期
  "focus": "把睡觉时间稳定在 23:30 之前",
  "habits": [
    {
      "id": "hxxxx",
      "line": "health",            // health | money | skill | relation
      "name": "运动 30 分钟",
      "kind": "train",             // train | plain
      "freq": { "type": "flex", "perWeek": 3 },
      "when": "20:00",
      "dur": 30,
      "steps": ["原地踏步 3 分钟…", "…"],
      "min": "换好衣服，做 1 组",
      "tpl": "wake",
      "off": false,
      "log": {
        "2026-11-25": {
          "st": "done",            // done | min | miss
          "mins": 28,
          "feel": "normal",        // easy | normal | hard
          "sum": "原地踏步 3 分钟；…",
          "note": "今天有点累"
        }
      }
    }
  ],
  "scores": [                      // 季度体检
    { "date": "2026-11-10T10:00:00.000Z",
      "values":  { "health": 6, "money": 6, "skill": 8, "relation": 4 },
      "desired": { "health": 9, "money": 8, "skill": 9, "relation": 8 } }
  ],
  "reviews": [                     // 周复盘
    { "date": "11月17日 周一", "done": "…", "fail": "…", "next": "…", "rating": 4 }
  ],
  "draft": { "done": "", "fail": "", "next": "", "rating": 0 },
  "money": { "save": 3000, "rate": 5, "years": 10 },
  "migrated": ""
}
```

### 旧版迁移

导入时会自动识别：

- **v1**（`fourlines.v1`，只有打卡）：打卡记录转成 `st: done`
- **v2**（`fourlines.v2`，有 perWeek）：`perWeek` 转成频率对象
- 名字里带「运动 / 跑 / 练 / 健身 / 散步」的条目自动变成跟练类型，并挂上全身唤醒模板

首次打开时如果检测到旧版数据，也会自动迁移一次，设置页会提示「已从旧版（v2）自动迁移」。

### 清空

设置 → 清空所有记录。清单、评分、复盘、记录全部重置为初始状态，**不可恢复**。清空前请先导出。

## 九、手机端适配

四个页面和所有弹层都做了移动端适配。

| 断点 | 行为 |
|---|---|
| > 880px | 双栏：主内容 + 右栏 |
| ≤ 880px | 单栏堆叠，右栏内容移到下方 |
| ≤ 600px | 移动端细节：底部抽屉、放大触控目标、输入框 16px |

具体处理：

- **弹层改成底部抽屉**：从屏幕下方升起，整宽、上圆角，单手能够到底部的按钮。
- **触控目标放大**：三态按钮、次级按钮、评分按钮、滑块拇指都加大到适合手指的尺寸。
- **输入框 16px**：避免 iOS Safari 聚焦时自动放大页面。
- **安全区适配**：底部留出 `env(safe-area-inset-bottom)`，全面屏不会被 Home 条挡住。
- **去掉点击高亮**：`-webkit-tap-highlight-color: transparent`，点击不闪灰块。
- **横向溢出**：所有网格和弹性布局都加了 `min-width: 0`，390px 宽度下无横向滚动。

验证过 390px 宽度下的：今天 / 训练 / 回顾（两段）/ 清单，以及设置、补记、编辑、换模板、计时五个弹层。

## 十、放到手机上用（GitHub Pages）

线上地址：**[superahua.github.io/life-system](https://superahua.github.io/life-system/)**

### 装到主屏（30 秒）

1. 手机浏览器打开上面的地址（Safari / Chrome 都行）
2. 分享菜单 → **添加到主屏幕**（Chrome 在右上角菜单里）
3. 以后从桌面图标点开：全屏、没有地址栏，和原生 App 差不多

### 部署的是什么

仓库根目录放的就是这份静态文件，`main` 一推送，GitHub Pages 自动重建（约 30 秒）：

| 文件 | 作用 |
|---|---|
| `index.html` | 首页入口，和 `生命系统.html` 内容完全一致，由 `node tools/build.mjs` 生成 |
| `manifest.webmanifest` | 主屏图标名、主题色、独立窗口 |
| `icon-192.png` / `icon-512.png` / `icon-180.png` | 主屏图标与 iOS touch icon |
| `sw.js` | 让「打开过一次之后没网也能开」：导航请求走网络优先，失败才读缓存 |

### 三条要记住的

- **服务端不存任何东西**。Pages 只把 HTML 发给你，记录仍然只写在这台手机浏览器的 `localStorage` 里。
- **手机和电脑的数据是分开的**。两边各记一份，想搬到一起就用「设置 → 导出 JSON / 导入 JSON」。
- **别用无痕模式**。关掉窗口数据就没了，和本地打开是同一个道理。

### 想更新线上版本

```bash
node tools/build.mjs      # README 注回应用 + 重新生成 index.html
git add -A && git commit -m "更新说明" && git push
```

推送后等半分钟刷新即可。缓存是网络优先，不会出现「改了但手机上还是旧版」。

## 十一、设计原则：为什么这样取舍

**1. 每页只有一个主动作**
今天 = 记录；训练 = 开始练；回顾 = 复盘；清单 = 维护。页面多了会瘫，动作多了也会瘫。

**2. 不惩罚断签**
断签不清零、不飘红、不发"你已失败"的提示。打卡类工具最大的失败原因，就是让用户觉得自己已经失败了。

**3. 三态而不是两态**
留一个「最小版」的台阶，比逼用户二选一更能让人坚持下去。

**4. 训练要独立成页**
训练和"点一下打卡"是两种行为：一个需要连续 20–40 分钟的注意力，一个只需要 2 秒。放在同一页会让今天清单被训练撑长，也会让训练入口淹没在待办里。所以：今天页保留一键直达（开始跟练），训练页负责看计划、换模板、看历史。

**5. 砍掉等级和徽章**
XP 十级、27 枚徽章、补签卡，是给"每天打卡"设计的外部激励，和"每周 / 每季度审视"的节奏打架，还占首屏。这套工具的目标不是让人每天回来点一下，而是半年后回头看，四条线都还在。

**6. 不存 API Key**
本地文件跨域请求不可靠，Key 明文放在 localStorage 也不安全。所以只做「复制上下文」，你自己粘到任何对话框里问。效果一样，风险为零。

**7. 数据本地优先**
没有账号、没有服务器、没有隐私政策要看。代价是要自己导出备份，这个代价换来的确定性更高。

## 十二、常见问题

**Q：换电脑 / 换手机怎么办？**
导出 JSON，在新设备打开页面，导入。没有云同步。

**Q：能不能多设备同步？**
不能。要做同步必须有后端和账号，那会推翻「单文件、离线、无账号」的前提。

**Q：为什么完成率是 2.6/3 这种小数？**
「最小版」记 0.6。想要整数就只记「做了」。

**Q：连续天数为什么不是从今天算？**
今天还没记录时从昨天开始数，避免早上打开看到「连续 0 天」被打击。

**Q：跟练时会锁屏，倒计时还准吗？**
计时用的是时间戳差值（`endAt - now`），锁屏回来会重新对时，不会累积误差。但锁屏期间不会响铃。

**Q：能导出 CSV 给 Excel 吗？**
目前只有 JSON。JSON 里 `habits[].log` 就是按日期存的明细。

**Q：数据会被清掉吗？**
浏览器清缓存、无痕模式关闭、换设备都会。建议每周导出一次。

**Q：能改语言 / 主题吗？**
目前只有中文和这套浅色主题。深色模式需要额外维护一套配色，暂时没做。

## 十三、技术说明

| 项 | 说明 |
|---|---|
| 形态 | 单文件 HTML（约 128 KB，其中约 23 KB 是内嵌的这份说明；代码约 2250 行），CSS + JS 全部内联 |
| 依赖 | 无。不用框架、不用 CDN、不用构建 |
| 运行 | `file://` 直接打开即可，也可放到任意静态服务器 |
| 存储 | `localStorage`，键 `life.v3`（兼容读 `fourlines.v2` / `fourlines.v1`） |
| 弹层 | 原生 `<dialog>` + `showModal()` |
| 音频 | Web Audio API 合成提示音（880Hz / 160ms），不加载音频文件 |
| 布局 | CSS Grid + Flex，断点 880 / 600 |
| 图标 | 纯 CSS（品牌标记四个色块），无图标库 |
| URL | 支持 `#today` `#train` `#review` `#list` 直接进入对应页 |
| 说明页 | README 存在 `<script type="text/plain" id="docSrc">` 里，运行时用内置迷你 markdown 渲染器转 HTML。改完 README 后跑 `node tools/build.mjs` 同步，并顺带生成 `index.html`，不用手动复制 |
| 部署 | GitHub Pages 托管 `main` 根目录；`sw.js` 只缓存导航请求（网络优先），装到主屏后没网也能开 |

主要函数：

| 函数 | 作用 |
|---|---|
| `renderToday / renderTrain / renderReview / renderList` | 四个页面的渲染 |
| `habitWeek / weekStat / dayStat` | 周 / 日统计（加权） |
| `trainHabits / trainStats / recentTrain` | 训练数据聚合 |
| `parseStep / stepView` | 把自然语言步骤拆成 组数 / 秒数 / 休息 |
| `startTimer / tick / completeSet / saveTimer` | 跟练计时与落库 |
| `buildAIContext` | 生成给 AI 的复盘上下文 |
| `md2html / docSheet` | 把内嵌的 README 转成设置页里的说明文档 |
| `exportData / importData / migrateFrom` | 备份、恢复、旧版迁移 |
