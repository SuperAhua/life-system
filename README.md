> 一个单文件的个人节奏工具：**四条线不透支，今天的事今天做，训练单独练。**
> 双击 `生命系统.html` 即可使用，不用安装、不用联网、不用注册。数据只存在你自己的浏览器里。
> 想让它**到点弹出来叫你**，装安卓 App 版（见第十一节）；想让它**读懂你的记录再说话**，接一个模型（见第十二节）。

## 一、这是什么

大多数人回望 25–35 岁，后悔的不是没赚到钱，而是**健康透支、错过积累、放弃了关系**。

这个工具把这句话拆成四条线：

| 线 | 一句话 | 颜色 |
|---|---|---|
| 健康 | 身体是所有目标的底座 | 绿 |
| 财务 | 不透支，也别让钱闲着 | 琥珀 |
| 能力 | 一项别人难以替代的本事 | 蓝 |
| 关系 | 父母的陪伴有期限 | 玫红 |

围绕这四条线，它只做三件事：

1. **今天**：把清单里该做的事摆出来，点一下记录（做了 / 最小版 / 没做）
2. **训练**：跟练计时，一个动作一个动作走完，自动落库
3. **回顾**：每周回答三个问题，每季度给四条线打分，看哪条在透支

它不追求"全"，追求**能长期用下去**。所以没有等级、没有徽章、没有连续打卡惩罚，也没有排行榜。

## 二、五分钟上手

### 打开

双击 `生命系统.html`，用 Chrome / Edge / Safari 打开即可。也可以拖进浏览器窗口。

手机上不用传文件：直接开 [线上地址](https://superahua.github.io/life-system/)，再「添加到主屏幕」（见第十节）。

### 第一次打开会看到什么

- 已经预置了 8 条清单（四条线各 2 条），可以直接用，也可以全改掉
- 顶部四个页签：**今天 / 训练 / 回顾 / 清单**
- 右上角齿轮：数据与设置

### 每天（30 秒）

打开「今天」，从上往下做。做完点「做了」；状态不好点「最小版」——它也算数。

### 每周（5 分钟）

去「回顾 → 本周复盘」，先看上半部分的自动统计，再回答三个问题，保存。

### 每季度（10 分钟）

去「回顾 → 季度体检」，四条线各给「现在」和「期望」打个分，看差距最大的那条。

### 训练（想练的时候）

去「训练」，跟练台已经挑好了今天该练的那条，点「开始跟练」→「开始」，跟着倒计时走。不想跟计时就直接点「做了」或「最小版」。

### 想让它更懂你（可选）

设置 → AI 教练 → 选 DeepSeek → 填 Key → 保存 → 测试连接。之后训练页会多一张「教练说」，可以问它任何关于记录的问题，也可以直接说「今天练完了，20 分钟」让它替你记。

## 三、四个页面

### 1. 今天

**这一个页面的主动作：记录今天。**

- **抬头一句判断**：今天还剩几件 / 都记完了 / 某条已经几天没做。只给一句，不刷屏。
- **本周重点**：只写一件，做完就算赢。随时可改。
- **今日清单**：按时间排序。每条显示时机、频率、本周进度；当前该做的那条会被标上「现在」。
- **三种状态**：做了（绿）/ 最小版（琥珀）/ 没做（红）。再点一次可以取消。
- **展开行**（点标题）：看到 SOP 步骤、最小版、上次记录，还能写一句备注。跟练条目的底部多两个入口：「换一套」「去训练页 ›」。
- **跟练条目**多一个「开始跟练」，直接进计时器。
- **右栏「这一周」**：7 根竖条（当天完成率）+ 四条线的本周完成度 + 连续天数。

底部还有「补记昨天」，忘了勾的可以补。

### 2. 训练

**这一个页面的主动作：打开就能练，不用先点开弹层。**

- **抬头一句判断**：本周还差几次 / 今天练过了 / 本周已达标。
- **跟练台**（页面第一张卡）：默认自动挑「今天还没练」的那一条，显示动作数、预计时长、起手动作，右上角是本周进度。点「开始跟练」→ 就地列出全部动作 → 点「开始」进入计时。
- **计时就在这张卡里**：62px 的大号倒计时、当前动作、组数圆点、进度条，「完成这组 / 暂停 / 跳过动作」三个按钮一行。组间休息自动接，倒计时结束响一声。
- **不跟练也能记**：跟练台底部有「做了 / 最小版」两个小按钮，一键落库，不用进计时。
- **教练卡**：接了大模型就显示一句「今天最该做哪件事」，以及「问教练」「排今天的动作」两个入口；没接就是一行「去接入」，其余功能不受影响。
- **多条训练时**：跟练台会自动在「也可以练」里列出其它条目，点一下切换；同时在下方保留每条的设置卡（换动作 / 看动作 / 三态记录）。

如果一条跟练都没有，页面会给一个「+ 加一条训练」，点开就是预填好的表单。
- **右栏**：
  - 训练记录：本周次数、本周时长、本月次数、累计时长 + 7 天打卡条
  - 最近 8 条：日期、名称、分钟数、体感
  - 练过什么：从计时记录里摘出的动作组合（只在有记录时出现）

### 3. 回顾

顶部分段控件切换两个视角。

#### 本周复盘

- **这周的样子**（自动统计，不用你填）：四条线完成率、做了 / 最小版 / 没做各几条、记成没做的清单、你写过的备注。
- **周复盘三问**：这周做成了什么 / 哪里没做好、为什么 / 下周最重要的一件事。加一个 1–5 分自评。
- **最近 18 周热力图**：一格一天，颜色越深当天完成率越高，点格子能补记那一天。
- **复制给 AI**：把本周真实数据整理成一段话，粘到任何对话框里就能问"这周该改哪件"。

#### 季度体检

- **现状 / 期望双滑块**：每条线两条轨道，上面是现在，下面是期望。1–10 分。
- **雷达图**：形状就是你的四条线。
- **差距提示**：自动指出差值最大的那条，并建议「这个季度只补这一条」。
- **历次**：保存过的每次体检，显示四线均值与相对上次的 Δ。
- **算一算**：月存 × 年化 × 年数 → 复利终值，同时算出「晚 5 年开始会少掉多少」。

### 4. 清单

**这一个页面的主动作：维护清单。**

按四条线纵向分组。每行只有名称、标签（跟练 / 频率）、编辑按钮。所有增删改都在弹窗里完成，避免误触。

### 设置（右上齿轮）

- **到点提醒**：五项权限、测试响铃、晚间兜底、批量设时间（只在 App 里成立）
- **使用说明**：这份 README 已经内嵌进应用，离线也能看（顶部目录可一键跳到对应章节）
- **AI 教练**：开关、服务商、Key、模型、身体资料、测试连接
- 记录天数 / 记录次数 / 累计时长
- 导出 JSON / 导入 JSON / 清空所有记录
- 复制上下文（不填 Key 时，把本周数据整理成一段话给任意对话框）

## 四、核心概念

### 三态记录

| 状态 | 权重 | 什么时候用 |
|---|---|---|
| 做了 | 1.0 | 按计划完成 |
| 最小版 | 0.6 | 状态差，只做了台阶版 |
| 没做 | 0 | 明确没做 |

**为什么要有「最小版」**：只记「做了 / 没做」时，状态一差就只能记「没做」，连着记几天人就不想记了。留一个 0.6 的台阶，记录才不会断。

完成率 = Σ权重 ÷ 本周目标次数。所以会出现 `2.6/3` 这种小数，这是正常的。

### 每条清单的四要素（SOP）

1. **叫什么** —— 具体到能直接开始。写「运动 30 分钟」而不是「多运动」。
2. **什么时候** —— 给一个时间点，工具会把它排进今天，并在到点后标「现在」。
3. **分几步** —— 一行一步，最多 12 步。步骤的作用是降低启动成本。
4. **最小版** —— 今天实在不行时做的那一步，通常就是"换好衣服"。

### 频率的四种类型

| 类型 | 含义 | 本周目标 |
|---|---|---|
| 每天 | 天天做 | 7 |
| 每周 N 次 | 一周内任意 N 天 | N |
| 每周固定几天 | 只在选定的星期出现 | 选定天数 |
| 每月某天 | 每月固定日期 | 1 |

「每天」和「每周 N 次」的条目会出现在每天的清单里（因为哪天做由你决定）；「每周固定几天」和「每月某天」只在对应日子出现。

### 连续天数

只要当天**任意一条**有记录就算。今天还没记时，从昨天往前数——所以早上打开不会看到「连续 0 天」。

断签不清零、不飘红，只是数字停住。热力图里斜纹表示"那天没记录"，不等于"没做"。

## 五、训练模块

### 三个入口

1. **训练页的跟练台** —— 打开就在那儿，自动挑今天还没练的那条
2. 今天页跟练行的 **开始跟练** —— 一键跳到训练页并进计时
3. 到点提醒的**通知按钮** —— 不用进 App 就能记「做了 / 最小版」

### 什么算「跟练」

清单里的条目如果是「跟练（带计时）」类型，就会：

- 在「今天」的行里多出一个「开始跟练」按钮
- 出现在「训练」页
- 记录时能存下用时、体感、做了哪些动作

普通条目只有三态记录，没有计时。

### 六套预置模板

| 模板 | 侧重 |
|---|---|
| 全身唤醒 | 唤醒 + 全身循环，适合早上或久坐后 |
| 下肢 | 深蹲、箭步蹲、臀桥、静蹲 |
| 上肢 | 俯卧撑、推举、划船、卷腹 |
| 核心 | 平板、抬腿、死虫、登山跑 |
| 有氧 | 快走、慢跑、跳绳、波比 |
| 恢复 | 慢走、泡沫轴、猫牛式、拉伸 |

每套 6 行。点「换一套动作」可以整体替换步骤，**历史记录不受影响**。

### 计时是怎么工作的

每条步骤会被自动解析：

```
深蹲 4 组 × 15 个，组间休息 60 秒
   ↓
组数 4 · 组间休息 60 秒 · 单组不设倒计时（按次数做）
```

```
平板支撑 3 组 × 45 秒，组间休息 30 秒
   ↓
组数 3 · 单组 45 秒倒计时 · 组间休息 30 秒
```

规则：

- `N 组` → 组数（1–12）
- `组间休息 / 组间歇 / 组间 / 休息 / 间歇 + 数字 + 秒/分钟` → 休息时长
- 第一个「分钟 / 分」→ 单组倒计时；没有分钟时取「秒」
- 写了组数但没写休息 → 默认 45 秒
- 只写「3 公里」「20 个」这类 → 不倒计时，做完手动点

**不用写得规范**，认不出来就退化成「按次数做，做完点完成这组」。

### 一次完整跟练

1. 训练页第一张卡就是**跟练台**，点「开始跟练」→ 动作清单就地展开（不用弹窗）
2. 点「开始 · 共 N 个动作」→ 进入第 1 组，卡片变成大号计时器
3. 有秒数的自动倒计时，到点响一声（880Hz，160ms），自动进休息
4. 休息结束自动进下一组
5. 按次数做的，做完点「完成这组」
6. 三个按钮随时可用：完成这组 / 暂停 / 跳过动作；右上角「提前结束」
7. 走完最后一组 → 同一张卡变成完成态：用时、完成动作数、跳过数
8. 选一个体感（轻松 / 刚好 / 偏难），点「存进今天」

**不想跟计时**：跟练台底部有「做了 / 最小版」，点一下直接落库，不用进计时流程。

**多条训练**：跟练台底部「也可以练」列出其余条目，点一下切换；下面还保留每条的设置卡（换动作 / 看动作 / 三态记录）。只有一条时不显示设置卡，页面更干净。

存进去的内容：

```
st:   done          （状态）
mins: 28            （用时，多次累加）
feel: normal        （体感）
sum:  原地踏步 3 分钟；开合跳 3 组 × 30 秒；…   （做过的动作，≤140 字）
```

体感会进周复盘和给 AI 的上下文，下次「换一套」时可以据此调整强度。

### 训练页的统计口径

| 指标 | 口径 |
|---|---|
| 本周次数 | 本周内状态为「做了」的记录数 |
| 本周时长 | 同上，累加 mins |
| 本月次数 | 本月内「做了」的记录数 |
| 累计时长 | 所有训练记录的 mins 之和 |
| 7 天条 | 哪天有「做了」就亮 |

**最小版和没做不算次数**，只出现在「最近」列表里——避免"点一下最小版就当练过"的自我安慰。

### 响铃没声音？

浏览器要求先有一次用户交互才允许播放音频。点过页面任意位置后再开始即可。如果仍然没声，检查系统是否静音、浏览器是否限制了自动播放。

## 六、回顾：周复盘与季度体检

### 自动统计（不用填）

打开「本周复盘」，上半部分已经替你算好：

- 四条线的完成率（加权）
- 做了 / 最小版 / 没做各几条
- 记成「没做」的具体条目和星期
- 这一周你写过的备注

### 三个问题

1. **这周做成了什么** —— 写事，不写感受
2. **哪里没做好，为什么** —— 是时间不够，还是根本没开始
3. **下周最重要的一件事** —— 只写一件

加一个 1–5 分的整体自评。保存后进历史，右下角可以看更早的。

### 热力图

最近 18 周，一格一天。颜色分 5 级（无记录 / <34% / <67% / <99% / 100%）。点任意一格打开那天的补记面板。

### 季度体检

- 四条线各两个滑块：**现在** 和 **期望**
- 雷达图看形状，不看绝对高低
- 差距最大的一条会被点名，并建议这个季度只补它
- 每次保存进「历次」，带均值与 Δ
- 底部的复利计算器：默认月存 3000、年化 5%、10 年 → 约 46.6 万；晚 5 年开始只剩 20.4 万

### 复制给 AI 的上下文

点「复制给 AI」，生成的文本包含：

```
【我的四线周报】11月25日 周三
健康：本周 3/3（100%），做了 3、最小版 0、没做 0
财务：…
上次体检：健康 6/期望9，…
本周重点：…
训练：本周 3 次、101 分钟；累计 56 次、1724 分钟

【本周明细】
11/25 运动 30 分钟 = 做了 28分 刚好 内容:…
…

【上次复盘】做成：…；卡在：…；下周重点：…

请基于以上真实数据回答：1）这周哪条线透支最明显；2）下周只改一件事的话，改哪件；3）给一个能立刻做的最小动作。不要泛泛而谈。
```

粘到 DeepSeek / 豆包 / 任何对话框都能用。**不联网、不存 API Key**，这是刻意的选择。

## 七、清单管理

在「清单」页点「+ 加一条」或任意条目的「编辑」。

| 字段 | 说明 |
|---|---|
| 叫什么 | 具体到能直接开始 |
| 属于哪条线 | 健康 / 财务 / 能力 / 关系 |
| 类型 | 普通 / 跟练（带计时） |
| 频率 | 每天 / 每周 N 次 / 每周固定几天 / 每月某天 |
| 什么时候做 | 时间点，用于排序和「现在」标记 |
| 大概多久 | 分钟，仅作展示与训练页参考 |
| 分几步 | 一行一步，最多 12 步 |
| 最小版 | 今天实在不行时做的那一步 |

底部三个操作：**停用 / 删除 / 保存**。

- **停用**：从今天清单里消失，但历史记录保留，随时可以启用
- **删除**：连同历史记录一起删掉，不可恢复（会二次确认）

> 建议四条线加起来不超过 16 条。超过之后完成率一定会掉，掉完就不想看了。

## 八、数据与备份

### 存在哪

浏览器的 `localStorage`，键名 `life.v3`。**不上传、不联网、没有服务器。**

这也意味着：**换设备、换浏览器、清缓存，数据就没了。** 请定期导出。

### 导出

设置 → 导出 JSON，文件名形如 `生命系统备份-2026-11-25.json`。

### 导入

设置 → 导入 JSON，选择之前导出的文件。会校验版本：v3 直接读，旧版自动迁移。

### 数据结构

```jsonc
{
  "v": 3,
  "start": "2026-11-20",          // 开始使用的日期
  "focus": "把睡觉时间稳定在 23:30 之前",
  "habits": [
```

## 九、手机端适配

四个页面和所有弹层都做了移动端适配。

| 断点 | 行为 |
|---|---|
| > 880px | 双栏：主内容 + 右栏 |
| ≤ 880px | 单栏堆叠，右栏内容移到下方 |
| ≤ 600px | 移动端细节：底部抽屉、放大触控目标、输入框 16px |

具体处理：

- **弹层改成底部抽屉**：从屏幕下方升起，整宽、上圆角，单手能够到底部的按钮。
- **触控目标放大**：三态按钮、次级按钮、评分按钮、滑块拇指都加大到适合手指的尺寸。
- **输入框 16px**：避免 iOS Safari 聚焦时自动放大页面。
- **安全区适配**：底部留出 `env(safe-area-inset-bottom)`，全面屏不会被 Home 条挡住。
- **去掉点击高亮**：`-webkit-tap-highlight-color: transparent`，点击不闪灰块。
- **横向溢出**：所有网格和弹性布局都加了 `min-width: 0`，390px 宽度下无横向滚动。

验证过 390px 宽度下的：今天 / 训练 / 回顾（两段）/ 清单，以及设置、补记、编辑、换模板、计时五个弹层。

## 十一、安卓 App：到点提醒

网页版有个绕不过去的短板：**它没法在你不看它的时候叫你**。浏览器的定时器一旦切到后台就被系统冻结，关闭页面就彻底停了。这不是代码问题，是浏览器的权限天花板。

所以做了一个安卓 App。它不只是套壳——里面是原生闹钟。

### 装上去

手机浏览器打开（两个地址任选，哪个快用哪个）：

- **<https://superahua.github.io/life-system/life-system.apk>**
- <https://github.com/SuperAhua/life-system/releases/latest/download/life-system.apk>

下载完点开安装 → 如果提示「禁止安装未知来源」，去设置里允许这一次即可。

安卓 8.0 以上都能装。装完桌面上会出现四个色块的图标。

### 第一次打开：把五项权限打通

进「设置 ⚙ → 到点提醒」，会看到五个小胶囊。绿色是已开，灰色是没开——**点灰色那项会直接跳到对应的系统设置页**。

| 权限 | 不开的后果 |
|---|---|
| 通知 | 什么都弹不出来 |
| 精确闹钟（Android 12+） | 系统会把提醒挪到"大致这个时间"，可能差十几分钟 |
| 全屏提醒（Android 14+） | 锁屏时不会铺满整屏，只出一条通知 |
| 置顶显示（可选） | 有它才能在你正用别的 App 时直接把提醒页顶上来；没有就退化成顶部横幅 |
| 免电池限制 | 部分国产系统（MIUI / EMUI / ColorOS）会把 App 冻住，提醒可能不响 |

不同厂商的设置路径不一样，找不到就用搜索：在系统设置里搜「闹钟和提醒」「全屏通知」「显示在其他应用上层」。

**改完点一下「响一次试试」**，5 秒后会有一条测试提醒。看得见就说明链路通了。

### 每条清单设提醒

清单 → 编辑 → 「到点提醒」填一个时间（空着就不提醒）。

旁边的「同上」按钮会把「什么时候做」的时间复制过来，多数情况点它就行。

懒得上一条条改：设置里有个 **「按「什么时候做」批量设」**，一次把所有还没设提醒的清单，按它们各自的「什么时候做」时间填上。

几个规则：

- 只在该做的日子提醒。每周三五次的习惯，不会在周一吵你。
- **今天已经记过的，不再提醒**。提前打完卡，那个点的闹钟自动取消。
- 提前 7 天排一次。每次打开 App 会往后接，不用管。
- 提醒时间过了那一刻就不再补发，避免一次性弹一堆。

### 到点那一刻

选「全屏闹钟」模式时，屏幕会直接亮起来，盖在锁屏之上：

> **运动 30 分钟**
> 做不动就做这个：换好衣服，做 1 组
>
> 　　[ 做了 ]　　[ 只做最小版 ]　　[ 10 分钟后再提醒 ]

点「做了」或「最小版」，记录当场就写进去了，**不用先打开 App**。下次进 App 会提示「已按通知记上 1 件」。

不想被砸脸，就在设置里切成「只发通知」——那就只在下拉栏出一条，带同样的三个按钮。

### 晚间兜底

设置里还有一个「晚上兜底提醒」，默认 21:30。到点如果今天还有没做的，会再提醒一次，标题直接写「今天还剩 3 件」。

它的作用不是催，是**防止一天就这么过去了**。真不想被提醒，把时间框清空就关了。

### 网页版和 App 的数据是两份

App 里记的数据存在 App 自己的目录里，和浏览器那份互不相通（系统就是这么隔离的）。

要合并：一边「设置 → 导出 JSON」，把文件发到另一边，「导入 JSON」。

### 自己重新打包

改完 `生命系统.html` 后：

```bash
node tools/build.mjs      # README 注回应用，同时生成 www/
npx cap sync android      # 网页装进原生工程
cd android && ./gradlew assembleDebug
```

产物在 `android/app/build/outputs/apk/debug/app-debug.apk`。

第一次打包需要 JDK 21 和 Android SDK（`platforms;android-36`、`build-tools;36.0.0`）。不想在本地装这套东西的话，`tools/github-workflow-build-apk.yml` 是一份现成的云端构建配置：把它放到 `.github/workflows/build-apk.yml`，以后 push 就自动出包。

## 十二、AI 教练

前几版只做了「复制上下文」：把本周数据整理成一段话，你自己粘到 DeepSeek 网页版。能用，但每天复制一遍很烦，而且它看不到具体某天的动作。

这一版接了真的模型：填一个 Key，它就能直接读你的记录、回答问题、改清单。

### 怎么接（2 分钟）

设置 ⚙ → **AI 教练** → 「开启 AI 教练」→ 点一个服务商 → 填 Key → 保存 → 测试连接。

| 服务商 | 拿 Key 的地方 | 一个月的花费（按每天聊 3 句估） |
|---|---|---|
| **DeepSeek**（默认） | platform.deepseek.com → API keys | 几毛钱 |
| 通义千问 | 阿里云百炼控制台 | 有免费额度 |
| 智谱 GLM | open.bigmodel.cn | glm-4-flash 基本免费 |
| Kimi | platform.moonshot.cn | 有赠送额度 |
| 硅基流动 | cloud.siliconflow.cn | 有免费模型 |
| OpenAI | platform.openai.com | 贵，且需要外网 |
| Ollama 本地 | 电脑上跑 `ollama serve` | 免费，但手机要能访问电脑 |

接口地址填到 `/v1` 这一层就行，程序自己拼 `/chat/completions`。换服务商只改这一处。

### 它能做什么

1. **说一句今天最该做的事**（训练页「教练说」）
   读最近的记录，给一句 60 字以内的判断，可以点「换一句」重读。**同一天只请求一次**，结果缓存，不会每次打开都烧 token。

2. **对话**（「问教练」）
   像发微信一样问：「今天只有 15 分钟」「这周哪条线最差」「我膝盖不舒服」。它能看到你近 14 天的每一条记录、四线进度、训练明细、体检分数、上次复盘。

3. **直接改数据**（这一条最有用）
   你说「今天练完了，深蹲 3 组」，它不会回你「好的，请手动记录」，而是直接写进今天的记录，回复下面出现一张绿色小卡：

   ```
   [ 已记上「运动 30 分钟」20 分钟 ]   撤销
   ```

   点「撤销」就退回原样。能改的有四类：打卡（做了/分钟数/体感）、换动作计划、改每周次数、记住一条长期事实（伤病、作息、忌口）。

4. **本周复盘**（回顾页「教练的复盘」）
   读完两周数据，指出哪条线透支最明显、下周只改一件、明天能做的最小动作。180 字以内。

### 它能看到的和不能做的

**能看到**：四线本周进度、全部清单与频率、近 14 天逐条记录（日期/状态/分钟/体感/备注/练了什么）、训练统计、身体资料、上次体检、上次复盘、你让它记住的事。

**刻意限制**：

- **不许编**。系统提示里第一条就是「只能依据给定数据回答，数据里没有的直接说没有」。它不会编一个睡眠分数或心率。
- **必须具体**。要求引用哪一天、几次、多少分钟，不接受「你最近练得不错」这种话。
- **不诊断**。疼痛、伤病、胸闷、眩晕一律建议就医，不开运动处方。
- **不主动打扰**。它只在你点的时候说话。没有任何「AI 每日问候」推送到你脸上——这一条是看了 Google Health Coach 的教训才定下的（见下一节）。
- **不做订阅**。没有会员墙，没有"AI 次数用完请充值"。你付钱给模型厂商，不付给我。

### 花钱吗

你直接付给服务商，中间没有我。DeepSeek 一天聊三句、一周复盘一次，一个月大约几毛到两块。请求是**非流式**的，一次要等 2–8 秒，换来的是省电、省流量、App 里更稳。

### 为什么在 App 里更顺

浏览器直连模型需要服务商允许跨域。DeepSeek、通义、智谱、Kimi、硅基流动都允许，网页版直接能用。但有些服务商不允许，网页里就会报「请求失败」。

App 版在 `capacitor.config.json` 里开了 `CapacitorHttp`，所有请求走安卓原生 HTTP，**不受跨域限制**，任何 OpenAI 兼容接口都能连。

### 不接会怎样

什么都不会少。四个页面、跟练计时、到点提醒、周复盘、热力图，全部照常。教练卡变成一行「去接入」，回顾页那张卡变成一句说明。所有 AI 相关的代码都在 `aiReady()` 后面，关掉就是零开销。

## 十三、做之前看了什么：同类应用的毛病

这一版改训练页和加 AI 之前，把两类应用翻了一遍：习惯打卡类（Streaks、Habitify、Loop、Habitica）和 AI 健康教练类（Whoop Coach、Google Health Coach、MyFitnessPal AI、各家 AI 健身 App）。看的是它们被骂什么，而不是它们宣传什么。

### 六个被反复提到的毛病

**1. 连击（streak）崩塌 → 整体放弃**

习惯类应用最核心的机制是连续天数。但研究里有个反直觉的结论：允许自己断的人坚持得更久，追完美连击的人放弃得最快。因为连击一断，那个衡量你全部进度的数字就归零了，心理上等于"前面白做了"。

> 我们把连击彻底删了。今天看到的永远是「本周 2/3」，断一天只掉一格，周目标还在。热力图里那格是空的，不是红的。

**2. 功能越多，越没人用**

统计、图表、日记、社交、徽章、标签、子连击……每加一个功能，就多一个要维护的东西、多一个要做的决定。用户为了"简单"下载，结果维护一套比习惯本身还复杂的系统。

> 我们的取舍：四个页签，砍掉了 XP、27 枚徽章、补签卡、月历、柱状趋势、部位雷达、体重体脂曲线。清单默认 8 条，不是 20 条。

**3. AI 编造不存在的数据和功能**

Whoop Coach 的用户在官方论坛发帖，说它给了一套「app 里根本没有的选项」的详细操作步骤，被追问后承认是「从别的健身应用的模式里推测的」。Google Health Coach 也被指「误报运动数据、误解你告诉它的目标」。有评测者说它的训练建议"很泛"——会说你的 HRV 高于同龄人平均，但说不出这个平均来自哪个数据集。

> 三条防线：① 系统提示第一条就是「只能依据给定数据」；② 要求引用具体日期和数字；③ 我们的数据只有你自己记的，它编也只能编出你能一眼看穿的假日期。

**4. AI 全天候说话 → 用户去设置里关掉**

Google Health Coach 一天好几次在主屏更新评论，结果一批 Premium 用户专门去搜「怎么关掉 AI 教练」。MyFitnessPal 做得更收敛：AI 放在独立入口，你去找它它才说话。

> 我们也做收敛的那一版：训练页一句、回顾页一段，其余全靠你点。没有推送，没有"早安"。

**5. 建议泛泛，因为它只有问卷**

Reddit 上对 AI 健身 App 最集中的批评是「基于问卷的通用建议，换个人也成立」。能给出有用建议的，都是能读到真实训练数据的。

> 我们喂的是：近 14 天逐条记录（含体感、备注、练了什么）、四线进度、训练统计、身体资料、上次复盘。它想泛也泛不起来，因为数据太具体了。

**6. 数据上云 + 订阅墙**

习惯数据是很私密的东西（你在戒什么、你在怕什么）。而主流应用的趋势是把它放到服务器上，再按月收费。

> 没有账号、没有服务器、没有订阅。数据在 localStorage，Key 在你自己的设备里，请求直连服务商。

### 保留下来的优点

不是所有东西都该砍。这几条是同类应用里真正有效的：

| 优点 | 我们的做法 |
|---|---|
| 记录要一秒完成 | 今天页每条清单三个按钮，点一下即存；跟练台底部直接「做了/最小版」 |
| 视觉比数字有动力 | 18 周热力图、7 天打卡条、四线进度条 |
| 每周复盘才看得出模式 | 回顾页固定三个问题 + 自动统计 + AI 点评 |
| 低门槛版本能救命 | 每条清单都有「最小版」，记了算 0.6 次，不算失败 |
| 环境提示比提醒有效 | 提醒只做「到点一次 + 晚间兜底」，不做每小时催 |

### 一条结论

这类工具能不能用下去，不取决于功能多少，取决于**断掉之后它还愿不愿意让你回来**。所以整套设计里最重要的一行不是连击天数，是那个「最小版」按钮。

## 十四、设计原则：为什么这样取舍

**1. 每页只有一个主动作**
今天 = 记录；训练 = 开始练；回顾 = 复盘；清单 = 维护。页面多了会瘫，动作多了也会瘫。

**2. 不惩罚断签**
断签不清零、不飘红、不发"你已失败"的提示。打卡类工具最大的失败原因，就是让用户觉得自己已经失败了。

**3. 三态而不是两态**
留一个「最小版」的台阶，比逼用户二选一更能让人坚持下去。

**4. 训练要独立成页**
训练和"点一下打卡"是两种行为：一个需要连续 20–40 分钟的注意力，一个只需要 2 秒。放在同一页会让今天清单被训练撑长，也会让训练入口淹没在待办里。所以：今天页保留一键直达（开始跟练），训练页负责看计划、换模板、看历史。

**5. 砍掉等级和徽章**
XP 十级、27 枚徽章、补签卡，是给"每天打卡"设计的外部激励，和"每周 / 每季度审视"的节奏打架，还占首屏。这套工具的目标不是让人每天回来点一下，而是半年后回头看，四条线都还在。

**6. Key 只存在你的设备里，没有中间服务器**
接模型有两种做法：把 Key 存在我这边的服务器（省事，但你得信任我），或者存在你的浏览器里、直连服务商（麻烦一点，但没有第三方经手）。选后者。代价是网页版受跨域限制，所以另做了 App 版走原生 HTTP 绕过去。「复制上下文」保留着，不填 Key 也能用。

**7. 数据本地优先**
没有账号、没有服务器、没有隐私政策要看。代价是要自己导出备份，这个代价换来的确定性更高。

## 十五、常见问题

**Q：换电脑 / 换手机怎么办？**
导出 JSON，在新设备打开页面，导入。没有云同步。

**Q：能不能多设备同步？**
不能。要做同步必须有后端和账号，那会推翻「单文件、离线、无账号」的前提。

**Q：为什么完成率是 2.6/3 这种小数？**
「最小版」记 0.6。想要整数就只记「做了」。

**Q：连续天数为什么不是从今天算？**
今天还没记录时从昨天开始数，避免早上打开看到「连续 0 天」被打击。

**Q：跟练时会锁屏，倒计时还准吗？**
计时用的是时间戳差值（`endAt - now`），锁屏回来会重新对时，不会累积误差。但锁屏期间不会响铃。

**Q：能导出 CSV 给 Excel 吗？**
目前只有 JSON。JSON 里 `habits[].log` 就是按日期存的明细。

**Q：数据会被清掉吗？**
浏览器清缓存、无痕模式关闭、换设备都会。建议每周导出一次。

**Q：能改语言 / 主题吗？**
目前只有中文和这套浅色主题。深色模式需要额外维护一套配色，暂时没做。

**Q：AI 要花钱吗？能关吗？**
要，但很便宜（DeepSeek 一天聊三句大约几毛钱一个月），钱直接付给服务商。设置 → AI 教练 → 「关掉 AI」，所有 AI 功能立刻消失，其余功能不受影响。

**Q：API Key 会被上传吗？**
不会。Key 存在你设备的 `localStorage`，请求从你的设备直连服务商。这个项目没有服务器。

**Q：为什么 AI 一次要等好几秒？**
用的是非流式请求，一次吐完整段。换来的是省电、省流量、在 App 里更稳。想要逐字出，需要 SSE 流式，App 的原生 HTTP 层不支持。

**Q：AI 会不会瞎编我的数据？**
提示词第一条就是「只能依据给定数据，没有的直接说没有」，并要求引用具体日期和数字。但它仍然是模型，不是数据库——看到它对不上的数字，去「今天」或「最近」核对一下，错了就点「撤销」。

**Q：为什么训练页没有「连续打卡 X 天」了？**
故意去掉的。连击一断，人会觉得自己全盘失败然后彻底放弃，这是习惯类应用最常见的死因（见第十三节）。

## 十六、技术说明

| 项 | 说明 |
|---|---|
| 形态 | 单文件 HTML（约 200 KB，其中约 44 KB 是内嵌的这份说明；代码约 2800 行），CSS + JS 全部内联 |
| 依赖 | 无。不用框架、不用 CDN、不用构建 |
| 运行 | `file://` 直接打开即可，也可放到任意静态服务器 |
| 存储 | `localStorage`，键 `life.v3`（兼容读 `fourlines.v2` / `fourlines.v1`） |
| 弹层 | 原生 `<dialog>` + `showModal()` |
| 音频 | Web Audio API 合成提示音（880Hz / 160ms），不加载音频文件 |
| 布局 | CSS Grid + Flex，断点 880 / 600 |
| 图标 | 纯 CSS（品牌标记四个色块），无图标库 |
| URL | 支持 `#today` `#train` `#review` `#list` 直接进入对应页 |
| 说明页 | README 存在 `<script type="text/plain" id="docSrc">` 里，运行时用内置迷你 markdown 渲染器转 HTML。改完 README 后跑 `node tools/build.mjs` 同步，并顺带生成 `index.html`，不用手动复制 |
| 部署 | GitHub Pages 托管 `main` 根目录；`sw.js` 只缓存导航请求（网络优先），装到主屏后没网也能开 |
| 外壳 | Capacitor 8（`com.superahua.lifesystem`），把 `www/` 包进 WebView，minSdk 24 / targetSdk 36 |
| 提醒 | 自写原生插件 `Alarm`：`AlarmManager.setAlarmClock()` 精确排程 + `NotificationCompat.setFullScreenIntent()` + 独立 `AlarmActivity`（`showWhenLocked` / `turnScreenOn`） |
| 回写 | 通知按钮 → `BroadcastReceiver` 写 SharedPreferences 队列 → 下次进 App 由 `takePending()` 取走写进 `localStorage`，所以 App 没在前台也能记录 |
| 排程策略 | JS 把未来 7 天展开成具体时刻交给原生，每次启动/回前台重排；已打卡的时刻自动跳过；重启后由 `BootReceiver` 重排 |
| 大模型 | OpenAI 兼容的 `/chat/completions`，**非流式**。App 里开 `CapacitorHttp` 走原生 HTTP 绕过 CORS；网页里直连服务商（需其允许跨域） |
| 提示词 | 系统提示在 `AI_PERSONA` + `ACT_DOC` 里，数据在 `aiData()` 里拼。AI 改数据靠末尾的 ` ```act ` 块，一行一个 JSON，由 `splitActs / runActs` 解析执行，可撤销 |

主要函数：

| 函数 | 作用 |
|---|---|
| `renderToday / renderTrain / renderReview / renderList` | 四个页面的渲染 |
| `habitWeek / weekStat / dayStat` | 周 / 日统计（加权） |
| `trainHabits / trainStats / recentTrain` | 训练数据聚合 |
| `parseStep / stepView` | 把自然语言步骤拆成 组数 / 秒数 / 休息 |
| `startTimer / tick / completeSet / saveTimer` | 跟练计时与落库（计时器在训练页内嵌，不用弹层） |
| `trainDeck / deckIdle / deckDots` | 跟练台的三态渲染：空闲 / 计时中 / 完成 |
| `buildAIContext` | 生成给外部 AI 的复盘上下文（不填 Key 时用） |
| `aiData / aiSystem` | 把真实记录拼成上下文 + 系统提示（防幻觉规则 + act 协议） |
| `callAI` | 一次非流式请求。App 里优先 `CapacitorHttp.request`，否则 `fetch` |
| `aiSend / coachSheet / coachMsg` | 对话发送、渲染、消息气泡 |
| `splitActs / runActs / undoAct` | 解析 AI 回复里的动作、执行、撤销 |
| `aiDaily / aiWeekly` | 当天一句建议、本周点评（都按天/按周缓存，不重复请求） |
| `md2html / docSheet` | 把内嵌的 README 转成设置页里的说明文档 |
| `exportData / importData / migrateFrom` | 备份、恢复、旧版迁移 |
| `buildAlarms / syncAlarms` | 把清单展开成未来 7 天的提醒时刻，交给原生排程 |
| `drainPending` | 把通知里点掉的「做了 / 最小版」补进记录 |

原生侧（`android/app/src/main/java/com/superahua/lifesystem/`）：

| 文件 | 作用 |
|---|---|
| `AlarmPlugin.java` | 给网页层的接口：`schedule / takePending / status / test / openSettings / askNotifications` |
| `AlarmScheduler.java` | `setAlarmClock` 排程与撤销，没有精确闹钟权限时逐级降级 |
| `AlarmReceiver.java` | 到点发通知（含三个动作按钮）、拉起全屏页、处理延后 10 分钟 |
| `AlarmActivity.java` | 全屏提醒页：亮屏、盖在锁屏上，三个按钮直接落库 |
| `AlarmStore.java` / `Perm.java` / `BootReceiver.java` | 本地队列、权限检查与跳转、开机重排 |
